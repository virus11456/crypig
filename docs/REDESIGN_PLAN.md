## 1. UI/UX 重新設計

### 1.1 現況問題（2026-11-18 線上版截圖觀察）

| # | 問題 | 影響 |
|---|---|---|
| 1 | **頁首三排雜訊**：2 個分頁、3 個姊妹站、2 個交易所開戶、一整行時間戳，再加 13 個美股連結 | 手機版第一屏全被連結佔滿，看不到內容；13 個美股連結和加密貨幣主題無關，稀釋品牌、像廣告站 |
| 2 | **時間戳是一整串長字串**（行情／分析／資格檢查／市值／跨所 OI） | 一般使用者看不懂，只需要知道「資料新不新、有沒有異常」 |
| 3 | **用 emoji 當圖示**（🐷📊🐋🧠🎯🌐💰📋…） | 各平台顯示不一、風格不統一，是「廉價感」的主要來源 |
| 4 | **視覺層級平**：每個區塊都是同樣的深色框和折疊卡，重點數字和說明文字大小相近 | 掃讀困難，看不出先看哪裡 |
| 5 | **市場背景有 7 張一模一樣的長條折疊卡往下疊**，策略頁也全是折疊卡 | 頁面很長、單調，桌機寬螢幕右半部空著 |
| 6 | **CSS 多輪疊加**：同一元件被覆寫 3～4 次，到處寫死色碼（`#101820`、`#142634`…） | 顏色、間距、圓角不一致，越改越難維護 |

### 1.2 設計系統（ui-ux-pro-max 產出）

- 查詢：`crypto trading analytics dashboard dark data-dense`，設定 density 8、variance 3、motion 2。
- **風格**：Minimalism & Swiss Style，深色、格線、高對比、以功能為主。適合專業工具和儀表板。
- **色彩 token**（新增在 `:root`，所有元件都只引用 token）：

| Token | 值 | 用途 |
|---|---|---|
| `--bg` | `#0a0e15` | 頁面底色 |
| `--surface` / `-2` / `-3` | `#10161f` / `#141c27` / `#1a2431` | 卡片、卡內區塊、表頭三層 |
| `--border` / `--border-strong` | `#1f2a38` / `#2c3a4d` | 分隔線、互動元件框 |
| `--fg` / `--fg-2` | `#e8eef6` / `#c3cfdc` | 主文字、次文字 |
| `--mut` / `--mut-2` | `#8d9bad` / `#677589` | 說明、標籤（≥ 4.5:1 對比） |
| `--accent` | `#5eaefc` | 互動、目前分頁、圖示 |
| `--bull` / `--bear` / `--warn` | `#2fbf71` / `#f0575a` / `#e3a33b` | 多、空、警示（不只靠顏色，另附文字） |

- **字體**：設計系統原本建議 Fira Code／Fira Sans，但這兩套字型不含中文。改用系統字（PingFang TC、Noto Sans TC、微軟正黑體），數字一律用 `font-variant-numeric: tabular-nums` 對齊。不載入外部字型，保持速度。
- **間距**：4 / 8 / 12 / 16 / 24 / 32。**圓角**：8 / 12 / 16。
- **圖示**：用 Lucide SVG sprite（`<symbol>` 加 `<use>`）全面取代 emoji，加上 `aria-hidden`。
- **動態**：hover／展開 150–250ms；遵守 `prefers-reduced-motion`。
- **檢查清單**：觸控目標 ≥ 44px、focus ring 看得見、可用鍵盤操作、在 375 / 768 / 1024 / 1440 寬度下不出現橫向捲動。

### 1.3 改版內容

#### A. 頁首改成單列 App bar（最大的視覺改善）

```
┌──────────────────────────────────────────────────────────────────────┐
│ [icon] HypeBoss 大戶行為觀察台 │ 行為觀察 │ 策略研究 │   ● 資料即時・12 秒前  ▦ 工具 ▾ │
└──────────────────────────────────────────────────────────────────────┘
```

- **品牌**：App 圖示加「HypeBoss」，取代 🐷 emoji。
- **分頁**：改成 segmented control，`aria-current="page"` 標示目前所在頁。
- **資料狀態膠囊**：用綠、藍、黃燈號加一句短文字（「資料即時・12 秒前」或「部分資料延遲」）。點開才看到完整的行情、分析、資格、市值、OI 明細（沿用 `#ts`，內容不變）。
- **「工具」下拉選單**：收納交易所開戶、姊妹站和相關工具（含 13 個美股連結和 TradingBeats）。點選單外面或按 Esc 會關閉。
- **手機（≤ 720px）**：兩個分頁移到**底部 tab bar**，拇指可及。頁首只留品牌、狀態燈和工具鈕。

#### B. 頁尾

- 品牌加上分組連結（姊妹站／相關工具），用低調的文字連結，不用按鈕框。

#### C. 行為觀察頁

- 導讀區縮小字級，錨點改成膠囊按鈕。
- 三個群體卡統一使用 surface token。區塊編號改成 accent 色小方塊。摘要句放大加粗，兩欄摘要各自成為子卡。
- 「市場背景」改成**桌機 2 欄格狀**：展開的卡自動佔滿整列，幣別總表固定全寬。

#### D. 策略頁

- 新增頁面標題區。
- 卡片改成 2 欄格狀，訊號驗證固定全寬。

#### E. CSS 整併

- 先新增「Design System v2」token 層統一外觀（P1、P2）。
- 再逐段刪除被覆寫的舊規則和寫死的色碼（P3）。

### 1.4 分階段與驗收

| 階段 | 內容 | 風險 |
|---|---|---|
| **P1** | App bar、工具選單、狀態膠囊、底部 tab bar、頁尾、token、SVG 圖示 | 低：不動資料或 JS 渲染邏輯，只改外框 |

## 2. 自建功能（取代嵌入 TradingBeats）

我們已經在抓 Hyperliquid 的資料：`crypig/clients/hyperliquid.py` 有 `clearinghouseState`、`userFills`、`slim_accounts_bulk`，`crypig/storage/account_positions.py` 也有逐輪持倉快照。所以以下兩個功能都用自有資料完成，不依賴第三方。

### 2a. 知名地址動態（優先）

**目標**：像社群動態一樣，用白話呈現知名大戶的倉位變動，並和分歧雷達連動。

- **地址清單**：新增 `config.yaml` 的 `notable_addresses`，欄位有 `address`、`alias`、`x_url`、`source`。只收錄公開資訊已揭露的地址，並且可以合併現有巨鯨和聰明錢名單裡持倉最大的帳號。
- **事件偵測**（每輪 cycle 比對上一筆持倉快照，不另外打 API）：
  - 事件類型：開倉／加倉／減倉／平倉／翻向／被清算（倉位歸零，且前一筆價格已越過 `liquidationPx`）。
  - 門檻：名目 ≥ $50 萬，或倉位變動 ≥ 20%，避免洗版。
- **白話文案**：用**模板**產生，不依賴 LLM，可以測試。
  - 例：「補倉做空 BTC $338 萬，總倉位 $2,282 萬（20x）；均價 64,340，目前浮虧 $11 萬。」
  - 只陳述觀察到的事實，不寫「看多」「抄底」之類的預測。這和現有頁面「不推測原因」的原則一致。
- **儲存**：在 `crypig/storage/` 新增 `notable_events`（時間、地址、幣、事件類型、前後部位、價格、文案）。
- **API**：`GET /notable-feed?limit=50&coin=BTC`
- **前端**：行為觀察頁新增「知名地址動態」卡片。
  - 時間軸列表顯示頭像字母、別名、事件標籤、白話句和部位小表。
  - 可以篩選幣種。
  - 每筆附上該幣當下的群眾情緒方向（取自分歧雷達），標出「大戶與群眾反向」。
- **測試**：事件偵測（各類事件與門檻）、文案模板、資料缺漏時不產生假事件、API 回應格式。

### 2b. 清算價分布（「清算熱力圖」）

**限制說明**：Hyperliquid 沒有官方的全市場清算熱力圖 API。我們只能統計**已追蹤帳號**的清算價，必須在介面上清楚標示「追蹤樣本，非全市場」。

- **計算**：每輪取追蹤帳號（巨鯨、聰明錢、知名地址）各幣持倉的 `liquidationPx` 與名目，依「相對現價 ±%」分桶加總，多倉和空倉分開。
- **API**：`GET /liquidation-map?coin=BTC`，回傳現價、各價格桶的多倉／空倉清算名目、樣本帳號數、資料時間。
- **前端**：首版做「價格軸 × 清算名目」的雙向長條圖，多倉在下方、空倉在上方，標出現價線。先支援 BTC／ETH／HYPE。暫不做 treemap，因為樣本有限，treemap 容易被誤讀成全市場規模。
- **測試**：分桶邊界、缺 `liquidationPx` 的帳號排除並揭露數量、樣本數過少時顯示「樣本不足」。

### 2c. 建議順序

1. **UI P1**：先把外觀的廉價感拿掉。
2. **2a 知名地址動態**：資料大多已有，差異化最高。
3. **UI P2**。
4. **2b 清算價分布**。
5. **UI P3**：清理舊 CSS。
